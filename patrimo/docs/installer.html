Suivi budgétaire et patrimonial

Installer Patrimo

Une application web auto-hébergée, à installer sur son Mac, son PC, ou un serveur — et à ajouter à l'écran d'accueil d'un iPhone comme d'un Android. Partageable avec un proche, chacun son profil. Compter vingt minutes la première fois.

D'abord

Choisir sa voie

Les trois installent la même application. Elles diffèrent sur un seul point : depuis où l'on peut y accéder.

Commencer ici

Sur sa machine

Mac ou PC. Pour vérifier que l'import de ton relevé fonctionne avant d'investir dans quoi que ce soit.

Gratuit · 20 min
Ensuite

Machine + Tailscale

Même installation, plus un accès chiffré depuis l'iPhone où que tu sois. Tant que la machine reste allumée.

Gratuit · +10 min
Usage quotidien

Serveur

Un VPS et un sous-domaine. Disponible en permanence, y compris ordinateur éteint.

≈ 5 €/mois · +30 min

Les trois se cumulent : ce qui est installé en local se redéploie sur un serveur sans rien réécrire. Seule la base de données ne suit pas — les opérations importées en local sont à réimporter, ce qui ne coûte rien puisque la déduplication empêche les doublons.

Sur sa machine

Installation

Choisis ton système : les commandes ci-dessous s'adaptent.

01

Installer Docker

Docker fait tourner l'application et sa base de données sans rien installer d'autre sur ton système.

Docker fait tourner l'application et sa base de données sans rien installer d'autre. Sur Windows, il s'appuie sur WSL 2 — l'installeur le propose et le configure.

Terminal 
$ brew install --cask docker

Sans Homebrew, télécharger l'installeur sur docker.com. Prendre la version Apple Silicon pour un Mac M1 ou plus récent.

Télécharger Docker Desktop sur docker.com et suivre l'installeur. Un redémarrage est demandé la première fois.

Lance l'application Docker une première fois avant de continuer. Tant que la baleine n'est pas dans la barre de menus, la commande suivante échouera.

02

Extraire le projet

Décompresse patrimo.tar.gz là où tu veux garder le projet.

Terminal 
$ cd ~/Documents
$ tar xzf ~/Downloads/patrimo.tar.gz
$ cd patrimo
PowerShell 
> cd ~\Documents
> tar -xzf ~\Downloads\patrimo.tar.gz
> cd patrimo

tar est livré avec Windows 10 et 11. Inutile d'installer 7-Zip.

03

Lancer le script d'installation

Il vérifie Docker, génère les clés de chiffrement, écrit la configuration, construit l'image et démarre. Rien à saisir.

Terminal 
$ ./scripts/setup.sh
PowerShell 
> .\scripts\setup.ps1

Si Windows bloque l'exécution, autorise-la pour cette session seulement : Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

La première construction prend trois à cinq minutes. Les suivantes, quelques secondes. Le script attend que l'application réponde avant de rendre la main.

04

Créer ton profil

Rends-toi sur localhost:3000. L'application demande un prénom et un code à 4 à 12 chiffres. Ce premier profil est propriétaire de l'installation : lui seul pourra en ajouter d'autres.

Elle propose ensuite deux façons de démarrer — importer un relevé, ou saisir simplement ton solde actuel. Les deux se complètent, et l'écran se saute.

Ce code n'est pas récupérable. La page qui crée le premier profil n'est atteignable qu'une seule fois ; ensuite elle redirige vers l'écran de connexion.

05

Importer un relevé

Depuis l'espace client de ta banque, exporte tes opérations en OFX si le format est proposé, sinon en CSV. Puis écran Importer dans l'application.

L'OFX porte un identifiant unique par opération et le solde du relevé : la déduplication devient exacte, et le prévisionnel s'ancre sur un solde réel plutôt que sur un cumul de mouvements. Réimporter un fichier déjà traité ne crée jamais de doublon — tu peux y aller sans réfléchir.

Sur téléphone

Ajouter à l'écran d'accueil

L'application s'installe comme une vraie app : icône dédiée, plein écran, pas de barre d'adresse. Trois gestes, sur iPhone comme sur Android.

Safari · iOS

2. Bouton Partager  (le carré avec la flèche)
3. Sur l'écran d'accueil  →  Ajouter
Chrome · Android

1. Ouvrir l'adresse de l'application dans Chrome
2. Menu  ⋮
3. Installer l'application  →  Installer

Sur une adresse en http://, Chrome ne propose que
« Ajouter à l'écran d'accueil » : un raccourci, sans hors ligne.

Quelle adresse utiliser

C'est ici que le HTTPS entre en jeu — et il ne sert pas à ce qu'on croit. L'ajout à l'écran d'accueil et le plein écran fonctionnent aussi en http://. Ce que le HTTPS débloque, c'est le service worker, donc le mode hors ligne et le cache du code.

Adresse Depuis où Hors ligne Ce qu'il faut
http://192.168.x.x:3000 Le Wi-Fi de la maison non Rien
https://…​.ts.net Partout oui Tailscale
https://finance.mondomaine.fr Partout, machine éteinte oui VPS + domaine

L'adresse IP locale est affichée par le script d'installation à la fin, juste sous l'adresse localhost.

Accès hors de la maison, sans louer de serveur

Tailscale Serve place ta machine sur un réseau privé chiffré et lui attribue un nom en .ts.net avec un vrai certificat — sans domaine à acheter ni port à ouvrir sur ta box.

Sur la machine qui héberge 
# Après avoir installé Tailscale et connecté l'iPhone au même compte
$ tailscale serve 3000

À vérifier avant de compter dessus : la documentation de Tailscale ne précise pas si Serve est inclus dans le plan personnel gratuit. Je ne l'ai pas testé — confirme-le sur leur page de tarifs.

Sur un serveur

Déploiement permanent

C'est la seule voie où l'application répond tout le temps, depuis n'importe quel téléphone, ordinateur éteint — et la seule où le partage avec quelqu'un a du sens.

De quoi la machine a besoin

Mesuré sur ce code : la construction Next.js culmine à environ 800 Mo de mémoire. Il faut y ajouter PostgreSQL et le système.

RAMVerdict
2 Go Passe, sans marge. Activer du swap avant de construire, sinon le build est tué en silence.
4 Go Confortable. Le choix par défaut.
PlusInutile ici.

Un seul cœur suffit, 20 Go de disque aussi. Et il faut une offre VPS ou serveur cloud : un « hébergement mutualisé » à 2 € ne fait tourner ni Docker ni PostgreSQL.

Combien ça coûte

OffreConfigPrix indicatif
Hetzner CAX11 (ARM) ou CX22 2 vCPU · 4 Go · 40 Go ≈ 4,50–5 € HT/mois
OVHcloud VPS Starter 1 vCore · 2 Go · 20 Go ≈ 3,50 € HT/mois
Scaleway DEV1-S 2 vCPU · 2 Go · 20 Go ≈ 8 € HT/mois

À vérifier avant de commander. Ces tarifs viennent de comparatifs publics de septembre 2026, pas des sites des hébergeurs. Les grilles bougent souvent — confirme le prix et la config sur la page de l'hébergeur.

Le moins cher qui tienne vraiment : environ 5 à 6 € TTC par mois, un serveur ARM à 4 Go plus un nom de domaine. L'image Docker se construit sans rien changer sur ARM, et un Mac Apple Silicon est déjà sur la même architecture. Le nom de domaine coûte une dizaine d'euros par an — ou rien du tout avec un sous-domaine gratuit type DuckDNS, qui fonctionne aussi avec Caddy et Let's Encrypt.

GitHub n'est pas un hébergement

À lever tout de suite, parce que c'est le malentendu qui coûte le plus cher : mettre le code sur GitHub ne fait pas tourner l'application. GitHub stocke du code. GitHub Pages sert des fichiers statiques — or il y a ici un serveur Node et une base PostgreSQL, donc Pages ne peut pas l'exécuter. Il faut une machine, dans tous les cas.

Ce que le dépôt apporte, c'est le chemin de mise à jour : au lieu d'envoyer une archive à chaque correction, le serveur fait un git pull.

Sur le serveur, les fois suivantes 
$ ./scripts/deploy.sh

Il récupère, reconstruit, redémarre, et attend que l'application réponde. .env et la base ne sont jamais touchés : le code change, les données et les secrets restent.

Et Railway, Render, Fly.io ?

Ces plateformes déploient directement depuis un dépôt : un git push et l'application se met à jour. C'est confortable. Deux objections, dans cet ordre.

La première est le sujet même de ce projet. Les opérations bancaires vivraient dans une base gérée par un tiers, sur une infrastructure qu'on ne contrôle pas. Toute la conception ici part du choix inverse. Ce n'est pas une question de confiance envers ces sociétés, c'est une question de cohérence : si les données peuvent aller chez un tiers, autant utiliser Bankin' ou Finary, qui font le travail mieux et gratuitement.

PlateformeApplication seuleOffre gratuite
Render≈ 7 $/mois Oui, mais le service s'endort après ~15 min
Fly.io≈ 7 $/mois Non pour les comptes créés après oct. 2024
Railway≈ 10–15 $/mois Non, un crédit d'essai

Ces chiffres de septembre 2026 sont indicatifs et ne couvrent que l'application : la base PostgreSQL gérée se facture en plus. On arrive à 12–30 € par mois, soit deux à cinq fois le prix d'un VPS qui fait tourner les deux. À vérifier sur leurs pages de tarifs.

La bonne combinaison : dépôt GitHub pour le code et les mises à jour, VPS pour l'exécution et les données. On garde le confort du git push sans confier ses relevés à qui que ce soit.

Les trois commandes

Avant de commencer : créer un enregistrement DNS de type A qui pointe le sous-domaine choisi vers l'IP du serveur.

Sur le serveur, puis sur le Mac, puis sur le serveur 
# 1. Sur le serveur neuf (Debian ou Ubuntu)
$ ssh root@<ip-du-serveur>
$ curl -fsSL https://get.docker.com | sh

# 2. Recuperer le projet — depuis le depot git...
$ git clone git@github.com:<toi>/patrimo.git && cd patrimo

#    ...ou, sans depot, en envoyant l'archive depuis le Mac :
#    scp patrimo.tar.gz root@<ip>:~  puis  tar xzf patrimo.tar.gz

# 3. Installer
$ rm -f docker-compose.override.yml
$ ./scripts/setup.sh --vps

Supprimer docker-compose.override.yml n'est pas cosmétique : ce fichier publie le port 3000 sur l'hôte, ce qui exposerait l'application sans HTTPS à côté de Caddy.

Caddy obtient le certificat Let's Encrypt dans la minute. S'il n'arrive pas, la cause est presque toujours le DNS pas encore propagé, ou le port 80 fermé. Les sauvegardes démarrent en même temps : une par jour dans ./backups, conservées trente jours.

Deux choses à faire tout de suite, pas plus tard : copier ENCRYPTION_KEY hors de la machine (gestionnaire de mots de passe), et vérifier le lendemain que ls backups/ renvoie bien un fichier. Une sauvegarde qu'on n'a jamais vue tomber n'est pas une sauvegarde.

À plusieurs

Partager avec quelqu'un

Une installation, plusieurs personnes. Chacune a son profil, son code, ses comptes — invisibles des autres. Ton ami n'installe rien : il ouvre la même adresse depuis son téléphone, choisit son profil, saisit son code. Ajouter l'icône à son écran d'accueil se fait exactement pareil.

Ajouter un profil
1. Réglages  →  Profils  →  Ajouter un profil
2. Son prénom, le code qu'il choisit, et ton code pour confirmer
3. Il ouvre l'adresse, appuie sur sa pastille, saisit son code

Son profil démarre vide, avec ses propres catégories.
Il ne verra jamais tes opérations, ni toi les siennes.

Ce que « cloisonné » veut dire exactement. Les profils séparent les données à l'intérieur de l'application. Mais toi, qui administres le serveur, tu peux lire la base directement. C'est un partage entre proches, pas un service anonyme — dis-le-lui clairement avant qu'il y mette ses relevés.

Pour que l'adresse soit joignable depuis son téléphone à lui, il faut sortir du réseau local : Tailscale ne suffit pas s'il n'est pas sur ton réseau. La voie « serveur + domaine » décrite plus haut est la seule qui marche partout, pour tout le monde, tout le temps.

Publier le code

Mettre le projet sur GitHub

Le dépôt ne contient que du code. Les opérations vivent dans PostgreSQL, les secrets dans .env, et ni l'un ni l'autre n'est versionné. Publier le dépôt ne publie donc rien de personnel — à condition de le vérifier une fois, avant.

Avant de publier 
$ ./scripts/check-before-push.sh

Le script regarde ce qui est réellement suivi par git et ce qui est réellement dans l'historique — pas ce que le .gitignore prétend. Aucun .env, aucun relevé, aucune sauvegarde, aucune valeur de secret.

Le piège qu'on découvre trop tard : retirer un fichier du dépôt ne le retire pas de l'historique. Un .env commité une seule fois reste lisible dans tous les commits suivants, même après git rm. Si le script signale ce cas, le plus sûr n'est pas de réécrire l'historique — c'est de repartir d'un dépôt neuf : rm -rf .git && git init. Et si un secret est parti malgré tout : le considérer comme compromis et le régénérer. Supprimer le dépôt ne suffit pas.

Deux façons de partager, à ne pas confondre

Même serveur, deux profils Dépôt GitHub, deux installations
Ce qui est partagé Le serveur et sa base Le code seulement
Où vivent ses données Chez toi Chez lui
Peux-tu lire ses données Oui, via la base Non, jamais
Ce qu'il installe Rien, il ouvre une URL Docker, et son instance
Qui paye le serveur Toi Chacun le sien, ou personne

Si ton ami sait lancer Docker, la voie GitHub est meilleure. Elle supprime la seule vraie réserve du partage par profil — que l'administrateur du serveur puisse lire la base — et t'évite d'être responsable des données financières de quelqu'un d'autre. Garde le partage par profil pour quelqu'un qui ne veut rien administrer.

Sans fichier LICENSE, un dépôt public reste « tous droits réservés » : le code est visible, mais personne n'a le droit de s'en servir. Si l'intention est qu'on puisse l'utiliser, ajouter une licence MIT est une ligne de plus.

Ensuite

Le rythme réel

Une fois par mois — trois minutes

Exporter le relevé, l'importer, puis passer sur Opérations → filtre Non catégorisées et classer ce qui reste. Chaque correction crée une règle : au troisième mois, il ne reste presque rien à faire. Saisir aussi les valorisations patrimoniales — écran Patrimoine → Mettre à jour à la main —, trente secondes par source.

Au quotidien — dix secondes

L'accueil répond à une seule question : est-ce que je peux dépenser ça. Solde projeté de fin de mois, dépenses en cours, alertes.

Le choix du mode budgétaire

Commencer en Suivi. Après deux mois d'historique, le bouton « Proposer des budgets » calcule la médiane de tes dépenses réelles plutôt que de te faire deviner. Ne passer en Enveloppes que pour la discipline base zéro : c'est un engagement quotidien, pas un réglage. La bascule est réversible sans rien perdre.

Quand ça coince

Dépannage

« Cannot connect to the Docker daemon »

Docker est installé mais l'application n'est pas lancée. Ouvre Docker Desktop et attends que l'icône de baleine se stabilise dans la barre de menus, puis relance le script.

Le script s'arrête sur « n'a pas répondu dans le délai imparti »

La construction a réussi mais l'application ne démarre pas. Les journaux disent pourquoi :

Terminal 
$ docker compose logs -f app

La cause la plus fréquente : le port 3000 est déjà pris par autre chose. Changer '3000:3000' en '3001:3000' dans docker-compose.override.yml, puis relancer.

L'import est refusé : « aucune colonne de libellé reconnue »

Le format de ta banque n'est pas encore reconnu. L'écran d'import affiche les colonnes trouvées dans ton fichier — il suffit de les ajouter au profil correspondant dans src/server/import/csv.ts, une dizaine de lignes.

Seul le profil BoursoBank a été confronté à un vrai export. Les autres viennent de formats publiquement documentés et peuvent demander cet ajustement.

L'app s'ouvre dans Safari avec la barre d'adresse

Une ancienne version du manifeste est en cache. Retire l'icône de l'écran d'accueil, recharge la page dans Safari en maintenant le bouton de rechargement, puis réinstalle.

Un profil a oublié son code

Si c'est celui de quelqu'un d'autre : Réglages → Profils depuis le profil propriétaire, qui peut réinitialiser le code des autres. Les données sont conservées.

Si c'est le code du propriétaire, il faut passer par la base, depuis la machine qui héberge. La commande ci-dessous supprime tous les profils et toutes leurs données :

Terminal 
$ docker compose exec db psql -U patrimo -d patrimo \
    -c 'DELETE FROM "Profile";'

C'est irréversible. Les opérations, budgets et valorisations partent avec. Si l'historique compte, restaurer d'abord une sauvegarde de ./backups.

Comment mettre à jour sans perdre mes données

Extraire la nouvelle version par-dessus l'ancienne, puis reconstruire. .env et la base de données ne sont pas touchés ; les migrations s'appliquent au démarrage.

Terminal 
$ docker compose up -d --build

Le README.md du projet couvre l'architecture, le cloisonnement des profils, les connecteurs Trade Republic et Yomoni, et les limites assumées de chacun.
Sauvegarde ENCRYPTION_KEY ailleurs que sur la machine : la changer rend illisible tout ce qui a déjà été chiffré.
